앞서 만든 이식 계획서의 그룹 A/B를 바로 붙일 수 있는 코드로 구체화했습니다. 아래 파일들을 순서대로 적용하세요.

적용 순서

① DB

Supabase → SQL Editor 에 schema.sql 붙여넣고 Run. Storage에서 ax 버킷 생성(산출물 파일용).

② ax_port.js 연결 — ADAPTER 3곳

// ax_port.js 상단
const sb = window.supabase || window.sb;        // ← ilsan-AX의 Supabase 클라이언트 변수
function currentUser(){ return window.MY_NAME; } // ← presence/로그인 이름
const SCHED = () => window.SCHEDULES;            // ← ilsan-AX WBS 배열 [{id,title,goal,progress}]

그런 다음 앱 초기화 후 한 번 호출:

await axPort.init({ rerender: ()=>renderAllAxPanels() });
// 각 패널을 원하는 컨테이너에 렌더:

// 편집 잠금 버튼: 
// 주간보고 인쇄:
편집 잠금 게이트: ilsan-AX의 기존 저장/수정 함수 맨 앞에 if(!axPort.gate())return; 를 넣으면 잠금 상태에서 전 기능이 잠깁니다. 주요 변경 뒤 axPort.audit('상태 변경', 과제명) 를 호출하면 감사 이력에 남습니다.

④ AI-HOS 아키텍처 (재배선)

aihos_arch.css 포함 후 <div id="arch"></div> 에 renderArch(document.getElementById('arch')). 번들 상단 주석의 외부 의존성을 ilsan-AX 값으로 연결하세요:

번들이 기대하는 것ilsan-AX에서 연결
GOALS, goalOf(code)growth_cycle.js의 GOALS 재사용
TASKS[code] {name,goal,details,outputs}ax_schedules 레코드로 매핑 함수 작성
STATE.taskProgress[code]과제 진척값
STATE.outputs[code]ax_outputs 또는 outcome 텍스트
노드 클릭 상세(openNode 내부의 드로어)ilsan-AX 상세 패널로 교체 가능(렌더 자체는 클릭 없이도 동작)
렌더링(노드·연결선·타임라인·루프·팬줌·전체화면)은 자기완결적입니다. 노드 클릭 상세만 ilsan-AX 방식으로 바꾸면 되고, 급하면 openNode 호출부를 비워도 다이어그램은 그대로 작동합니다.

그룹 C (세부추진과제 계층)

schema.sql에 ax_subtasks를 포함해 두었습니다. 도입 시: 과제 진척을 "세부과제 진행률 평균"으로 롤업, 3단계 간트(과제→단계→세부과제), 선행(dep) 기반 지연위험(⚠)까지 확장합니다. ilsan-AX의 마일스톤 기반 진척과 병행할지/대체할지 정책을 먼저 정하세요. 이 계층이 계획대비 flag의 정식판 전제입니다.

확인 필요: 이 키트는 ilsan-AX 정적 분석 기반입니다. Supabase 클라이언트 변수명, WBS 배열 구조, presence 이름 접근자만 실제 값으로 맞추면 동작합니다. RLS는 "전체 허용"이라 운영 전 병원 정책에 맞게 좁히세요.
